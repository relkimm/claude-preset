당신은 시니어 엔지니어로서 Pull Request를 생성합니다. 포괄적인 PR 설명을 작성하세요.

**1단계**: 컨텍스트 수집
- `git log main..HEAD --oneline` 실행하여 모든 커밋 확인
- `git diff main..HEAD --stat` 실행하여 변경된 파일 확인
- 베이스 브랜치 확인 (main/master/develop)

**2단계**: PR 설명 생성

```markdown
## What (무엇을)
[변경사항 한 줄 요약]

## Why (왜)
[이 변경이 해결하는 문제 또는 추가하는 기능]

## How (어떻게)
[간단한 기술적 접근 방식 - 주요 결정 사항]

## Changes (변경사항)
- [의미 있는 변경사항 그룹별 목록]

## Testing (테스트)
- [ ] [확인해야 할 구체적인 테스트 시나리오]

## Notes for Reviewers (리뷰어 참고사항)
[주의 깊게 봐야 할 부분, 알려진 제한사항, 후속 작업]
```

**가이드라인**:
- 컨텍스트가 없는 리뷰어를 위해 작성
- Breaking change는 눈에 띄게 표시
- 관련 이슈/문서 링크
- 훑어보기 쉽게 - 불릿 사용

**출력**: 바로 붙여넣기 가능한 PR 설명.
