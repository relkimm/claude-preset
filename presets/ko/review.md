코드를 리뷰하고 실용적인 피드백을 제공합니다.

## 사용법
- `/review` - 최근 변경 파일 리뷰
- `/review [파일경로]` - 특정 파일 리뷰
- `/review [PR번호]` - PR 변경사항 리뷰

## 리뷰 대상
- `$ARGUMENTS`에 파일 경로가 있으면 해당 파일
- PR 번호가 있으면 해당 PR
- 없으면 `git diff HEAD~1`로 최근 변경 확인

## 체크 항목

**버그 가능성**
- null/undefined 체크 누락
- 로직 오류, 조건문 실수
- 에러 처리 누락
- 경계 케이스 미처리

**보안**
- 사용자 입력 검증
- SQL 인젝션, XSS 위험
- 하드코딩된 비밀정보
- 권한 체크 누락

**코드 품질**
- 가독성 (명확한 네이밍, 구조)
- 중복 코드
- 불필요한 복잡성
- 성능 이슈

## 출력 형식

```
### 수정 필요
파일:라인 - [문제점]
해결: [구체적 수정 방법]

### 개선 제안
파일:라인 - [개선점]
이유: [왜 더 나은지]

### 잘된 점
- [긍정적 피드백]
```

## 원칙
- 친절하되 솔직하게
- 문제와 해결책을 함께 제시
- "무엇"과 "왜"를 모두 설명
- 괜찮으면 괜찮다고 말하기

사용: `/review` 또는 `/review src/api.js`
