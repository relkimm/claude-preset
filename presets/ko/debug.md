## 사용법
- `/debug` - 최근 에러 조사
- `/debug [에러 메시지]` - 에러 분석
- `/debug [문제 설명]` - 문제 조사

## 문제 파악
- `$ARGUMENTS`에 에러 메시지가 있으면 파싱
- 에러 종류, 위치, 파일, 라인 번호 확인
- 없으면 최근 변경사항 조사

## 조사
관련 코드 읽고 로직 흐름 따라가기:
- 변수명 오타
- import 누락
- null/undefined
- async/await 실수
- 타입 불일치
- 함수 인자 오류

## 출력 형식

```
원인: [무엇이 문제인지]

문제 코드:
[에러 발생 코드]

수정:
[고친 코드]

설명: [왜 발생했고 어떻게 해결했는지]
```

## 추가 단계
- 수정 후 테스트 방법 제공
- 비슷한 문제 예방 팁

사용: `/debug` 또는 `/debug TypeError: Cannot read property 'map'`
